# Growth Analyser

**Understand where you are. Discover where to grow.**

Growth Analyser analyzes publicly available GitHub activity to provide an estimated
technical skill profile, a portfolio health check, skill gaps, and personalized
learning priorities — grounded in what you've actually shipped, not a generic
checklist. Written advice is generated by **Google Gemini** (Google AI Studio).

## Features

- **GitHub-based skill detection** — reads your public repos (languages, names,
  descriptions, topics, recency) and scores your exposure to each skill, with
  evidence per skill (repo count, last used)
- **Career-goal skill gap analysis** — pick a target role and see what you're
  already strong in, developing, or missing; switch roles instantly
- **Role match across all 9 career paths** — see which role your profile fits best
- **Portfolio health score** — five measured dimensions (activity, consistency,
  documentation, impact, range) shown as a radar chart with plain-language notes
- **More stats** — stars, forks received, followers, language mix, 12-month activity
  strip, streaks, stale repos, documentation coverage (descriptions, topics, licenses,
  live demos), top repositories, and a breakdown of your latest public events
- **AI recommendations in two formats** — a prioritised **point-by-point** list
  (High / Medium / Low, with categories) and a **summary** narrative, plus
  **quick wins** you can tick off this week, strengths, and a **project to build
  next** with milestones
- **Learn Now / Learn Next / Pause For Now**, each with a reason tied to your data
- **Personalized 3-phase roadmap**
- **Download report** as Markdown
- Dark / light theme (remembers your choice), responsive down to phone width

## How it works

1. You enter a GitHub username and pick a target career (e.g. Full-Stack Developer)
2. The server reads your public profile, repositories and recent public events from
   the GitHub API (`/api/github`)
3. Skill scores, role matches and health scores are computed locally and
   deterministically — no AI involved in this step
4. A compact summary of those numbers is sent to Gemini (`/api/explain`), which
   writes the summary, recommendations, quick wins and project idea — the model
   explains the numbers, it doesn't invent them
5. Results render as a dashboard. If the AI call fails (or no key is set), the
   dashboard falls back to rule-based recommendations computed from the same data,
   so it's never empty

## Tech stack

- [Next.js 14](https://nextjs.org/) (App Router) + React + TypeScript
- GitHub REST API (public data only)
- [Google Gemini API](https://ai.google.dev/gemini-api/docs) via Google AI Studio
  (called with plain `fetch` — no SDK dependency)
- No database — fully stateless, nothing is stored server-side

## Getting started locally

```bash
npm install
cp .env.example .env.local   # then add GEMINI_API_KEY (see below)
npm run dev
```

Open [http://localhost:3000](http://localhost:3000).

## Environment variables

| Variable           | Required | Purpose |
| ------------------ | -------- | ------- |
| `GEMINI_API_KEY`   | Yes      | Powers `/api/explain`. Create a key in [Google AI Studio](https://aistudio.google.com/apikey). `GOOGLE_API_KEY` is also accepted. |
| `GEMINI_MODEL`     | No       | Gemini model to use. Defaults to `gemini-3.5-flash-lite`. If a model is unavailable or rate-limited, `gemini-3.8-flash` and then `gemini-2.5-flash` are tried automatically. See the [model list](https://ai.google.dev/gemini-api/docs/models). |
| `GITHUB_TOKEN`     | No       | Raises GitHub's rate limit from 60/hr (unauthenticated, shared across all visitors) to 5,000/hr and reads more pages of recent events. A plain personal access token with no special scopes works. Create one at [github.com/settings/tokens](https://github.com/settings/tokens) |

Never commit real values — `.env.local` is gitignored. Use `.env.example` as the
template.

## Deploying to Vercel

1. Push this repo to GitHub
2. Go to [vercel.com/new](https://vercel.com/new) and import the repository —
   Vercel auto-detects Next.js, no config needed
3. Add environment variables (Project Settings → Environment Variables):
   - `GEMINI_API_KEY` — required
   - `GITHUB_TOKEN` — optional but recommended
4. Deploy

Every push to your default branch redeploys automatically.

## Error handling

The app shows a plain-language message for:

- Username doesn't exist (404 from GitHub)
- GitHub rate limit reached (403) — includes a note about adding `GITHUB_TOKEN`
- Network/API errors reaching GitHub
- Empty/invalid username input

If Gemini can't be reached, the key is missing, or the key is rejected, the page says
why and shows data-based recommendations instead, with a **Try again** button. The
rest of the dashboard never depends on the AI call succeeding.

## Notes on scoring

- Skills are matched on whole words, so a JavaScript repo no longer counts toward
  Java.
- Forked repositories count for about a third of an original repository, since they
  mostly contain someone else's code. Portfolio-health statistics use your original
  repositories.
- Accounts with more than 100 public repos are read up to 300 repos (the most
  recently pushed).

## Privacy & limitations

Only publicly available GitHub information is read — no authentication or private
data access. The profile summary sent to Gemini contains aggregate statistics plus
the names, languages and descriptions of your top repositories. This produces an
**estimated** technical profile based on what's visible on GitHub; it can't capture
everything a developer knows (private repos, work done outside GitHub, non-coding
skills, etc.), so treat it as a starting point rather than a verdict.
